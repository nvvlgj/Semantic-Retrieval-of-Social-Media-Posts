# Semantic Retrieval System for the Kansas City Parade Shooting Dataset

## Overview

This project implements a semantic retrieval pipeline that identifies the most relevant documents for a given theme using sentence embeddings and cosine similarity.

The system consists of four stages:

1. Data preprocessing
2. Semantic document deduplication
3. Embedding generation and storage
4. Semantic retrieval

The implementation follows a modular architecture where each stage is responsible for a single task, making the pipeline easy to understand, maintain, and extend.

# Design Decisions

The implementation emphasizes clean software design by separating each stage into an independent module.

| Module | Responsibility |
|---------|----------------|
| preprocess.py | Text normalization and exact duplicate removal |
| semantic_deduplicator.py | Semantic duplicate detection using sentence embeddings |
| embedding.py | Generation and storage of the embedding bank |
| retrieval.py | Semantic search using NearestNeighbors |
| pipeline.py | Executes the complete workflow |

This separation makes each component reusable and independently testable.

---

# Task 1 – Data Preprocessing

The preprocessing stage performs lightweight text normalization while preserving semantic information.

### Processing steps

- Remove missing documents
- Normalize Unicode
- Remove URLs (optional)
- Normalize whitespace
- Remove exact duplicates
- Semantic document deduplication
- Save cleaned dataset

The preprocessing intentionally avoids aggressive NLP techniques such as:

- stemming
- lemmatization
- stop-word removal
- punctuation removal

These transformations may negatively affect sentence embedding quality.

---

# Semantic Deduplication

After removing exact duplicates, the pipeline performs semantic deduplication.

Instead of relying on lexical similarity (TF-IDF), the implementation uses sentence embeddings generated by:

```
sentence-transformers/all-MiniLM-L6-v2
```

Documents are embedded, indexed using `NearestNeighbors`, and compared using cosine similarity.

Semantically similar documents are grouped together, and one representative document from each group is retained.

This reduces redundancy in the corpus before generating the final embedding bank.

---

# Task 2 – Embedding Generation

The cleaned dataset is converted into dense vector representations using the pretrained model:

```
sentence-transformers/all-MiniLM-L6-v2
```

Reasons for choosing this model:

- Lightweight
- Fast inference
- Strong semantic retrieval performance
- Widely used baseline for semantic search

Embeddings are normalized during generation to enable efficient cosine similarity calculations.

Generated artifacts:

```
data/embeddings/

embeddings.npy
metadata.csv
embedding_info.json
```

`embedding_info.json` stores metadata describing the embedding bank, including:

- embedding model
- embedding dimension
- number of documents
- normalization status
- batch size

---

# Task 3 – Semantic Retrieval

The retrieval stage performs semantic search over the embedding bank.

Workflow:

1. Load document embeddings
2. Encode the search theme
3. Perform nearest-neighbor search using cosine distance
4. Convert cosine distance to cosine similarity
5. Return the Top-K most relevant documents

The implementation uses:

```
scikit-learn NearestNeighbors
```

rather than FAISS.

Given the dataset size, `NearestNeighbors` provides exact nearest-neighbor retrieval while keeping the implementation lightweight and portable.

For larger datasets, the retrieval layer can be replaced with FAISS without changing the remainder of the pipeline.

# Design Considerations

Several engineering decisions were made during implementation.

### Modular architecture

Each stage has a single responsibility and can be executed independently.

### Sentence embeddings

Sentence embeddings were selected over TF-IDF because they capture semantic meaning rather than lexical overlap.

### Normalized embeddings

Embeddings are normalized during generation, allowing cosine similarity to be computed efficiently during retrieval.

### Metadata separation

Embeddings are stored separately from document metadata, enabling the embedding bank to be reused with different retrieval strategies.

# Future Improvements

Several enhancements were identified during development.

## Corpus Representation

Instead of embedding the full article, generate embeddings using:

```
Title + first N characters of article content
```

This is expected to improve retrieval quality by emphasizing the most informative portions of each document.

- Replace `kneighbors()` with `radius_neighbors()`
- Cluster semantically similar documents
- Select the best representative document from each cluster
